# Global Progress Update - Документация изменений

## Обзор
Реализована система глобального прогресса игрока с детерминированной генерацией врагов и улучшенной механикой восстановления HP.

## Ключевые изменения

### 1. Глобальный прогресс игрока (не привязан к чату)

**Изменения в БД:**
- Таблица `player_progress` теперь не содержит `chat_id`
- Прогресс привязан только к `(user_id, season_id)`
- Новая таблица `chat_progress` отслеживает этажи в каждом чате

**Как это работает:**
- Игрок имеет один глобальный прогресс на сезон
- В разных чатах игрок может быть на разных этажах
- Предметы, золото, уровень - глобальные
- HP, текущий враг - глобальные

**Пример:**
```
Игрок в чате А: этаж 15
Игрок в чате Б: этаж 3 (начал играть позже)
Глобальный прогресс: этаж 15, все предметы и золото доступны везде
```

### 2. Боевое состояние (Combat State)

**Новая таблица `combat_state`:**
- Сохраняет текущего врага и его состояние
- Привязана к `(user_id, season_id)` - глобально
- Если игрок начал бой в чате А, он продолжит его в чате Б

**Механика:**
1. Игрок атакует врага в чате А
2. Враг получает урон, состояние сохраняется
3. Игрок переходит в чат Б
4. В чате Б продолжает бой с ТЕМ ЖЕ врагом
5. После победы или смерти состояние очищается

### 3. Детерминированная генерация врагов

**SeededRandom:**
- Враги генерируются на основе `(floor, season_id)`
- Все игроки на этаже 10 в сезоне 1 встречают ОДНОГО И ТОГО ЖЕ врага
- Боссы одинаковые для всех на боссовых этажах

**Преимущества:**
- Справедливость - у всех одинаковые боссы
- Возможность обсуждать стратегии
- Нет ситуации "мне попался легкий босс"

### 4. Восстановление HP

**Старая система:** HP восстанавливалось автоматически
**Новая система:**
- HP восстанавливается ТОЛЬКО:
  1. При использовании зелья (`/potion`)
  2. При переходе на следующий этаж (полное восстановление)
  3. При возрождении после смерти (на чекпоинте)

**Зелья:**
- Выпадают из врагов (20% шанс)
- Выпадают из боссов (100% шанс)
- Три типа: малое (30 HP), среднее (50% HP), большое (100% HP)
- Использование: команда `/potion` или `/зелье`

### 5. Система множественных чатов

**Награды:**
- **Первый чат (primary):** 100% наград
- **Дополнительные чаты:** 50% наград (золото и предметы)

**Прогресс:**
```
Чат А (первый):
- Игрок на этаже 20
- Награды: 100 золота за победу

Чат Б (второй):  
- Игрок начинает с этажа 1
- Награды: 50 золота за победу (50%)
- Предметы и уровень сохраняются
```

**Детали:**
- В `chat_progress` поле `is_primary_chat` определяет первый чат
- Первый чат, где начал игру, становится primary
- В других чатах награды умножаются на 0.5

## Миграция данных

**Запуск миграции:**
```bash
npm run migrate
```

**Файл миграции:** `src/database/migrations/004_global_progress.sql`

**Что происходит:**
1. Создаётся новая таблица `player_progress_global`
2. Данные переносятся из старой `player_progress`
3. Создаётся `chat_progress` для отслеживания этажей по чатам
4. Создаётся `combat_state` для сохранения боёв
5. Старая таблица переименовывается в `player_progress_old` (можно удалить позже)

## Новые команды

### `/potion` или `/зелье`
Использует зелье здоровья из инвентаря.

**Пример:**
```
/potion
> 🧪 Вы использовали Малое зелье здоровья
> 💚 Восстановлено: 30 HP
> ❤️ Текущее HP: 80/100
```

## Обновлённые команды

### `/status` или `/статус`
Теперь показывает:
- Глобальный прогресс (этаж, HP, статы)
- Прогресс в текущем чате
- Текущий бой (если есть)
- Предупреждение о низком HP
- Количество зелий

### `/inventory` или `/инвентарь`
Теперь показывает:
- Зелья с количеством
- Подсказку как использовать зелья
- Предметы и экипировку

## API изменения

### GameService.executeAction()
```typescript
// Старое
await gameService.executeAction(context, action, bypassCooldown);

// Новое - без изменений в сигнатуре, но внутри работает по-другому
await gameService.executeAction(context, action, bypassCooldown);
```

### PlayerProgressModel
```typescript
// Старое
await PlayerProgressModel.find(userId, chatId, seasonId);
await PlayerProgressModel.findOrCreate(userId, chatId, seasonId);

// Новое
await PlayerProgressModel.find(userId, seasonId); // без chatId!
await PlayerProgressModel.findOrCreate(userId, seasonId);
```

### ChatProgressModel (новый)
```typescript
// Получить прогресс в конкретном чате
await ChatProgressModel.find(userId, chatId, seasonId);
await ChatProgressModel.findOrCreate(userId, chatId, seasonId);

// Проверить, является ли чат основным
await ChatProgressModel.isPrimaryChat(userId, chatId, seasonId);
```

### CombatStateModel (новый)
```typescript
// Получить текущий бой
const combat = await CombatStateModel.find(userId, seasonId);

// Создать новый бой
await CombatStateModel.create({
  user_id: userId,
  season_id: seasonId,
  floor: 10,
  enemy_data: enemy,
  player_hp_before: 100
});

// Обновить состояние боя
await CombatStateModel.update(combatId, {
  enemy_data: updatedEnemy,
  rounds_completed: 3
});

// Очистить бой после победы/смерти
await CombatStateModel.delete(userId, seasonId);
```

### CombatEngine.generateEnemy()
```typescript
// Старое
const enemy = combatEngine.generateEnemy(floor);

// Новое
const enemy = combatEngine.generateEnemy(floor, seasonId);
```

### LootService.generateLoot()
```typescript
// Старое

// Новое
const loot = await lootService.generateLoot(
  floor,
```

## Тестирование

### Тест 1: Глобальный прогресс
1. Начните игру в чате А
2. Дойдите до этажа 5
3. Зайдите в чат Б
4. Проверьте `/status` - должен показать этаж 1 в чате, но этаж 5 глобально
5. Получите предмет в чате Б
6. Вернитесь в чат А - предмет должен быть в инвентаре

### Тест 2: Боевое состояние
1. Начните бой в чате А
2. Нанесите урон врагу
3. Переключитесь в чат Б
4. Атакуйте - должны продолжить бой с тем же врагом

### Тест 3: Восстановление HP
1. Получите урон в бою
2. Попробуйте `/potion` без зелий - должна быть ошибка
3. Победите врага (получите зелье от босса)
4. Получите урон
5. Используйте `/potion` - HP должно восстановиться

### Тест 4: Детерминированные враги
1. Создайте двух игроков
2. Оба дойдите до этажа 10
3. Проверьте босса - должен быть одинаковый

### Тест 5: Множественные чаты
1. Начните игру в чате А (primary)
2. Победите врага, запомните награду
3. Начните игру в чате Б
4. Победите врага - награда должна быть в 2 раза меньше

## Откат изменений

Если что-то пошло не так:

```sql
-- 1. Вернуть старую таблицу
DROP TABLE IF EXISTS player_progress;
ALTER TABLE player_progress_old RENAME TO player_progress;

-- 2. Удалить новые таблицы
DROP TABLE IF EXISTS combat_state;
DROP TABLE IF EXISTS chat_progress;

-- 3. Восстановить старые ограничения
ALTER TABLE cooldowns DROP CONSTRAINT IF EXISTS cooldowns_user_id_action_type_key;
ALTER TABLE cooldowns ADD CONSTRAINT cooldowns_user_id_chat_id_action_type_key 
  UNIQUE(user_id, chat_id, action_type);
```

## FAQ

**Q: Что происходит с прогрессом игроков после обновления?**
A: Миграция автоматически переносит данные. Берётся максимальный этаж из всех чатов.

**Q: Сохраняются ли предметы игроков?**
A: Да, все предметы сохраняются и доступны во всех чатах.

**Q: Можно ли играть одновременно в нескольких чатах?**
A: Да, но бой будет общим - если начали в чате А, продолжите в чате Б.

**Q: Как определяется основной чат?**
A: Первый чат, где игрок начал игру в текущем сезоне.

**Q: Можно ли сменить основной чат?**
A: Нет, основной чат определяется автоматически и не меняется в течение сезона.

## Производительность

**Оптимизации:**
- Индексы на `(user_id, season_id)` для быстрого поиска
- `combat_state` хранится в памяти БД (не в Redis)
- Детерминированная генерация не требует сохранения врагов в БД

**Нагрузка:**
- Дополнительные запросы: +2 на действие (combat_state, chat_progress)
- Объём данных: +10% (новые таблицы)

## Безопасность

**Защиты:**
- UNIQUE constraints предотвращают дубликаты
- Каскадное удаление при удалении пользователя
- Транзакции не требуются (одиночные операции)
